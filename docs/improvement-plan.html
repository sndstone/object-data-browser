04 / Delivery sequence

Improve in small, verifiable steps.

The sequence below describes the recommended scope. Optional P2 work follows the same gates; UI mockups are a design direction, not an instruction to rewrite the whole application.

01 · Trust

Make results reliable

Reproduce delete failure handling and transfer control routing. Fix the two P0 items, then add host deadlines, worker limits and diagnostic redaction.

Gate: failures stay visible; cancellation reaches the owning job; hung requests terminate predictably.
02 · Browsing

Recover the workspace

Implement the simpler toolbar, explicit search scope, honest row selection, readable density, and contextual inspector.

Gate: keyboard and touch workflows pass at 390, 700, 1000 and 1360 px, including large text and dark mode.
03 · Recovery

Make state understandable

Organize settings, distinguish task states, add safe metadata replacement, and make job-control capabilities accurate.

Gate: secure-save failures remain session-only; interrupted metadata writes recover; task UI matches engine state.
04 · Regression gates

Keep engines aligned

Run the expanded contract matrix and focused integration scenarios. Correct Go’s malformed-input behavior and enforce tests in CI.

Gate: Flutter analyze + full suite, mandatory built engines in CI, isolated storage integration tests; physical iOS checks before release.
05 / Evidence & boundaries

What this review establishes.

Inspected and checked

Reviewed the local working tree, including existing uncommitted iOS and UI work. Read the Flutter shell, browser, settings, jobs, theme, controller, persistence, desktop host and adapter; sampled Python, Go, Rust and Java request loops and transfer-control paths; inspected contracts and release workflows.

  • flutter analyze --no-pub: passed, no issues.
  • flutter test --no-pub --reporter expanded: all 92 tests passed.
  • Python standard-library subprocess checks: health, capabilities, unknown method, malformed JSON, 100 KB request, and survival all passed.
  • python3 -m pytest tests/contract -q: could not start because pytest is absent from the system interpreter. The smoke checks are not a substitute for the full contract suite.

No live storage operations, native screenshot capture, cloud integration runs, backend compilation matrix, or physical-device validation were performed. No measured performance claims are made.

Preserve what already works

  • Consolidated Keychain credential storage, metadata-only exports, hydration-failure blocking, and explicit secure-recovery boundaries.
  • Bounded text/image previews, selectable syntax highlighting, static HTML rendering, and no automatic script execution.
  • Adaptive navigation and the existing lazy object list. Do not propose adding virtualization that already exists.
  • Memoized object filtering/sorting and listing cancellation generations. Profile remaining bottlenecks before replacing these.
  • Automatic multipart sizing, bounded part workers, abort-on-failure behavior, signing rules and iOS local-network restrictions.
