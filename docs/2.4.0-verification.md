# Object Data Browser 2.4.0 build 3 verification

Verification ran locally on an Apple Silicon Mac and a Windows on ARM VM. The Windows VM ran the x64 payload under emulation.

## Application and engine checks

| Check | Result |
| --- | --- |
| Flutter analysis | No issues |
| Flutter tests | 1,226 passed, 9 skipped, including interoperability with reference `age` 1.3.1 |
| Python contracts | 494 passed, 42 skipped |
| Go | `go vet` and race-enabled tests passed. 493 contracts passed, 43 skipped |
| Rust | 68 native tests passed. 521 contracts passed, 15 skipped |
| Java | Gradle regression harness passed. 522 contracts passed, 14 skipped |
| Workflow and shell syntax | Passed |

The local suites exercised the shared age stream vectors in all four desktop engines. The final Java build includes a regression fix that preserves object names, cursors and request IDs containing short credential text. The benchmark contract test now gives the engine time to publish its final snapshot after the fixture receives the last request.

## Installers

- **macOS arm64, macOS 13 and newer.** The DMG passed image verification. The app bundle passed strict signature verification with empty effective entitlements and reported version 2.4.0 build 3. All four bundled engines passed health and offline contract smoke checks, and the bundled Java engine also passed the applicable storage-failure contracts. This development build is ad-hoc signed and uses the legacy Keychain. An update can require renewed Keychain authorization or credential re-entry.
- **Windows x64 and ARM64.** These are unsigned development MSIs. The rebuilds include the fixed Java sidecar. The packaging checks validate the engine manifest and run all four engine health checks for each architecture.
- **Android arm64.** APK Signature Scheme v2 verification passed with the Android Debug certificate. The APK reports version 2.4.0, version code 2003 and minimum Android API 24.

Release assets have SHA-256 checksums in `SHA256SUMS`. Tests used local fixtures. Live-provider workflows, physical-device behavior and Windows MSI upgrade behavior were outside this verification run.
