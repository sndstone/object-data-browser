# 2.3.3 verification

Version: **2.3.3+1**. Internal verification ran on an Apple Silicon macOS host on 2026-10-27.

## Internal CI

- Pinned actionlint and syntax checks for every `scripts/*.sh` file: passed.
- Flutter analysis: no issues. Full Flutter suite: **372 passed, 7 skipped**.
- Python contract suite: **146 passed, 42 skipped**.
- Go vet and race-enabled unit suite: passed. Contract suite: **145 passed, 43 skipped**.
- Rust unit suite: **15 passed**. Contract suite: **173 passed, 15 skipped**.
- Java Gradle build, transfer regression harness and distribution build: passed. Contract suite: **174 passed, 14 skipped**.
- Engine-specific skips reflect unsupported fixtures or provider features. These local contract runs use offline and loopback fixtures, not production cloud endpoints.

The internal checks use the same actionlint, Flutter and four-engine contract gates as repository CI, plus Go race checks, Rust unit tests and Java transfer regressions. They run on macOS; this is not cross-platform runner or Windows/Linux installer qualification.

## UI verification

New regressions cover the transfer banner phases (preparing until bytes or progress move, then transferring, paused, cancelling and the results), the banner copy without repeated percentages, the preparing banner before the engine reports a job for single and multi-file uploads, the file-scan versus multipart-segments selection, pause keeping the banner attached to its transfer, the banner returning to a completed upload after the automatic relist, and the activity mapping for quick actions, deletes and plain messages. Indicator tests confirm that nothing keeps animating with reduced motion or in paused and finished states.

Headless Flutter renders of every indicator state were reviewed in light and dark mode, including the preparing-to-transfer and working-to-result transitions. Three of the seven skipped tests are the new opt-in render captures (`DESIGN_GALLERY=1`); the other four were already skipped in 2.3.2. The renders use synthetic transfers and messages; they do not access stored credentials or real endpoints.

## macOS build

The release configuration builds for **arm64** with minimum macOS **12.0**. The local Xcode 27 invocation uses an external xcconfig setting `ARCHS=arm64`, `ONLY_ACTIVE_ARCH=YES` and `MACOSX_DEPLOYMENT_TARGET=12.0`; project deployment defaults are unchanged. This avoids Xcode's multi-architecture `lipo -verify_arch` parsing failure.

The DMG is an **ad-hoc signed development artifact**, with no Developer ID identity, notarization or sandbox/Keychain-group entitlements. It must not be represented as an update-safe production macOS package. Public distribution requires either the documented Developer ID lane or the user's explicit exception for a labeled development prerelease.

The final DMG was mounted read-only. The app passed strict/deep signature verification before and after testing. Bundle metadata reports version 2.3.3, build 1, arm64 and minimum macOS 12.0. Effective entitlements are empty. All required engine-manifest entries exist, packaged Python modules match their source, and every bundled engine reports 2.3.3 and passes **7 offline transport contract tests** from the mounted image.
