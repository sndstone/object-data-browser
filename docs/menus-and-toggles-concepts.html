How to get there

  1. Theme first (one change, covers all four menus). Add a popupMenuTheme to AppTheme._themeFromScheme that matches the panel tokens above. Every showMenu and PopupMenuButton then gets the surface, border, radius, shadow and padding.
  2. One shared row. Move the row from _AppSelectFieldState._menuItem into widgets/app_menu.dart as AppMenuRow, and add an appMenuItem(…) helper that returns a 40 px PopupMenuItem. Replace the ListTile and bare Text children with it. AppSelectField uses the same row, so the two can't drift apart.
  3. Same motion. Wrap showMenu in showAppMenu(…) with popUpAnimationStyle set to 180 ms / 120 ms easeOutCubic. Use PopupMenuPosition.under for button-anchored menus.
  4. Touch fallback. Set dropdownColor: scheme.surface and add the check to the selected item in the iOS/Android branch of AppSelectField.
// app_theme.dart — inside base.copyWith(...)
popupMenuTheme: PopupMenuThemeData(
  color: scheme.surface,
  surfaceTintColor: Colors.transparent,
  elevation: 6,
  shadowColor: scheme.shadow,
  menuPadding: const EdgeInsets.symmetric(vertical: 6),
  shape: RoundedRectangleBorder(
    borderRadius: BorderRadius.circular(10),
    side: BorderSide(color: scheme.outlineVariant.withValues(alpha: 0.9)),
  ),
  labelTextStyle: WidgetStatePropertyAll(
    textTheme.bodyMedium?.copyWith(fontWeight: FontWeight.w500)),
),

// widgets/app_menu.dart
PopupMenuItem<T> appMenuItem<T>({required T value, required String label,
    IconData? icon, bool selected = false, bool destructive = false, String? shortcut}) =>
  PopupMenuItem<T>(
    value: value, height: 40,
    padding: const EdgeInsets.symmetric(horizontal: 12),
    child: AppMenuRow(label: label, icon: icon, selected: selected,
        destructive: destructive, shortcut: shortcut));

Part 2 · Toggles

Your screenshot is the Appearance card. It shows three different switch looks in one card, because the theme only recolours the M3 switch and one row uses SwitchListTile.adaptive.

WHY

Three problems

  1. The adaptive switch is a different control. SwitchListTile.adaptive for “Compact desktop rows” renders a Cupertino switch on macOS: wider, with a white thumb and a grey track, and it ignores switchTheme.
  2. The same row also has different padding. It sets contentPadding: EdgeInsets.zero while its neighbours don't, so its switch sits 16 px further right. That is the misalignment in your crop.
  3. The M3 thumb changes size. It shrinks from 24 to 16 px when off and is a dark grey dot on a pale track. Combined with the muted “on” track (green at 72 %), the on and off states look like two different widgets.

The app has 21 SwitchListTiles (14 in Settings, 6 in Browser, 1 in Benchmark). Any of the designs below should go into one shared AppSwitch / AppSwitchTile so they all change together.

All eight designs below are clickable. Try them in dark mode too. Each one shows the same three Appearance rows, plus off, on, disabled and keyboard-focus states.

Recommendation: use 01 Forest pill as the default AppSwitch. On and off contrast clearly, it reads as a native control on macOS and Windows, and it fits the compact 36×20 desktop row. If you need a non-colour cue for accessibility, add the check and minus glyphs from 03 to the thumb. Keep 06 Segmented for the few settings where seeing the word “On” or “Off” helps more than a quick flip, such as Dynamic multipart sizing. If you want the smallest possible change, 02 Soft tint can be done with switchTheme alone.

Part 3 · Sliders

The app has three plain Sliders in Settings → Appearance and three coupled mix sliders in Benchmark. There is no sliderTheme, so they use Flutter's 2023 Material 3 slider.

NOW

Appearance sliders today

settings_workspace.dart:434–500
WHY

What to fix

  1. The unfilled track is almost invisible. It uses surfaceContainerHighest (#F3F5F0) on a white panel, at roughly 1.1:1 contrast, so you can't see where the range ends.
  2. The division dots add noise. The sliders have 16, 18 and 10 divisions, which render as rows of grey dots along the track.
  3. The value is inside the title. “UI scale: 100%” changes width while you drag. There are no min/max labels, no marker for the default, and no reset.
  4. The track doesn't line up with the text. The slider adds about 24 px of overlay padding on each side, so the track starts inside the title's left edge.
  5. The benchmark mix uses off-palette colours. Material teal, blue and red are used for three separate sliders that must sum to 100, which leads to a “Percentages must sum to 100” error state.

All eight designs below can be dragged, clicked, or adjusted with the arrow keys after you Tab to them. Each uses the real ranges, steps and defaults: Inspector 240–560 px in steps of 20 (default 360), UI scale 60–150 % in steps of 5 (default 100), and Log text 80–130 % in steps of 5 (default 80). Reset appears when a value differs from its default.

Dragging one slider silently moves another, and the colours aren't from the app palette. The control doesn't show visually that the three values are parts of one whole.

M1

Split bar

RECOMMENDED

One bar with two handles. The three parts always sum to 100, so the error state goes away. Colours come from the app: accent green for writes, the status blue for reads, and the error red for deletes. Presets cover the common workloads. Implementation: a custom MixBar widget using GestureDetector and CustomPaint, with keyboard support on both handles.

Slider recommendation: use S1 Forest rail as a shared AppSliderTile. It pairs with the Forest pill toggle: the same grey track, white thumb and green fill. It also adds a value chip, a default marker, min/max labels and a reset link. Most of it is a sliderTheme plus a small custom thumb and a track shape without side padding. Use S5's numeric field where exact values matter, such as the inspector size in pixels. Replace the benchmark sliders with the M1 split bar.
